# Backend bug sweep (cloud session)

Tests for bugs 1-7 live in `backend/tests/test_backend_bugs.py`. Each test was run red before the fix.

| # | Root cause | Fix | Test | Files |
|---|---|---|---|---|
| 1 | The SQLite `cache` table was only ever written to. | `Cache.prune(max_age_s, max_bytes)` deletes rows older than `CACHE_MAX_AGE_S` (30 days), then the oldest rows until the table is under `CACHE_MAX_BYTES` (200 MB). `scheduler.prune_cache` runs it every 6 hours (first run 5 minutes after start). | `test_cache_prune_by_age_and_size`, `test_scheduler_registers_cache_prune` | `cache.py`, `scheduler.py`, `main.py` |
| 2 | `Yahoo.quotes` already chunked (20 per request) but fired every chunk at once with `gather`, so 160+ symbols arrived as one burst. | At most `SPARK_PARALLEL` (2) chunks in flight, each holding its slot `SPARK_GAP_S` (0.15 s) after finishing. Chunk size stays 20 (below the 100 cap). | `test_yahoo_quotes_chunks_are_paced` | `providers/yahoo.py` |
| 3 | In `DataService._once` the leader ran the fetch inside its own task; cancelling the leader set `CancelledError` on the shared future, so waiters failed. | The fetch runs in a separate background task; every caller (leader included) only awaits `shield(fut)`. Cancelling a caller no longer touches the shared work. | `test_once_waiter_survives_cancelled_leader` | `service.py` |
| 4 | `DayStore.rows` ran zlib + msgpack decoding for up to 250 days on the event loop. | Blobs are read on the loop, then decoded in `asyncio.to_thread`. | `test_daystore_rows_decode_off_loop` | `world/india_store.py` |
| 5 | `return_measures` divided by `v[0]` or `v[0] + weighted`, which is zero or negative after big withdrawals; `xirr` bisected on `[-0.9, 10]` assuming one sign change, so two roots or a same-sign end pair gave a wrong answer or a false None. | Dietz, SIMPLE and TWR return `value: None` with a `NOT DEFINED` note when the base is not positive. `xirr` scans 400 points (log scale) for sign changes, bisects inside the single bracket, and returns None for no root or several roots (ambiguous). | `test_dietz_not_computable_after_big_withdrawal`, `test_return_measures_empty_start_value`, `test_xirr_finds_root_when_ends_have_same_sign` | `quantjobs/attr.py` |
| 6 | RISK valued each holding at its own series' last close, mixing days when one symbol's bars end earlier. | Market values use the last day common to all series (`px[-1]` of the aligned matrix); the first note now says `VALUED AT <date>, THE LAST DAY COMMON TO ALL HOLDINGS`. | `test_risk_valued_on_last_common_day` | `quantjobs/risk.py` |
| 7 | `parse_deribit` took `u[len(u) // 2]`, the upper median for an even count. | Even count uses the mean of the two middle values. | `test_deribit_forward_is_true_median` | `options/chain.py` |
| 8 | Not a real cache: leaked bench servers. `bench.mjs` spawned children without `detached`, so `process.kill(-pid)` threw (the child is not a group leader) and the fallback `c.kill()` stopped only the shell. `uv` and `python -m openterm` kept running on port 8000 with the old DB. The next run could not bind the port, talked to the old backend, and its first `risk` run hit that backend's jobs table. Reproduced with a small node script (attached child leaks a grandchild, detached does not). | `start()` spawns with `detached: !isWin` so `kill(-pid)` stops the whole tree; `main()` refuses to start if `/api/health` (8000) or 4173 already answers. | none (node script, repro only) | `scripts/bench.mjs` |

Skipped: none. No ported Vibe-Trading file was touched.

Note: leftover bench processes from an earlier run (python `-m openterm` on 8000, `vite preview` on 4173, started 17:48) were still alive when this was written. The new guard makes the bench refuse to run until they are stopped.
