Status: **approved as written 2026-10-18 (roadmap defaults pre-approved by the user); step 1 (spec, fixtures, tests) done.**
Fixtures: `scripts/record_phase15.py` (Yahoo 20y charts, SPDR sector ETFs, Ken French zips, doc-shaped Kite files); Vibe numbers: `scripts/vibe_quant15_crosscheck.py` -> `quant15_vibe_expected.json` (402 cases + 29 zoo factors).
Source: [ROADMAP_PHASES_11-19.md](../ROADMAP_PHASES_11-19.md) "Phase 15", [FEATURE_GAP.md](../FEATURE_GAP.md), Vibe-Trading `d0db2e3` (MIT:

Rule that shapes every choice: **never fake data, say what each number is.** A model with a missing input is **NOT RUNNABLE** and lists the
fields. Anything we compute is labelled computed; a scan on synthetic data says SYNTHETIC; Kite fixtures say NOT a recording.

## Decisions (defaults, approved)

| # | Decision | Default | Why |
|---|---|---|---|
| A | Heavy math | New package `openterm/quantlib/` (numpy, pandas, **scipy**), ported from Vibe with its header and a THIRD_PARTY.md row per file. **scipy, statsmodels and arch are added as dependencies** (Vibe's risk, copula, optimizers and HRP use `genpareto`, `chi2`, `t`, `rankdata`, `minimize`, `linkage`; its `timeseries` needs statsmodels for ADF, Engle-Granger, OU, hedge ratio and Granger, and `arch` for GARCH; rewriting them would break the cross-check). They are imported **only inside job kinds and tests**, never in the server process: `test_server_never_imports_scipy` covers scipy, statsmodels and arch (like the pandas test). `openterm/quant/` stays pure Python and light (Phase 14) | Cross-check parity; server import time |
| B | Jobs | Every function below runs as an internal job kind (`risk.run`, `opt.run`, `attr.run`, `fact.run`, `ql.run`, `alpha.scan`, `corr.regime`), submitted by `POST /api/quant/{fn}` (`fn` = `risk opt attr fact ql alpha regime`) with the parsed arguments as a JSON object. The server fetches the bars (router, cache, fixtures), writes a content-addressed data file (as `bt.run` does) and passes its path + hash; the job never touches the network. The answer is the job (`id`, `state`, `result`); a repeat is a cache hit (`state: done` at once). `result` is the standard envelope `{data, source, stale, age_s, fallback_from}` whose `data` is the **Phase 13/14 table payload** (`headline`, `sections`, `notes`, optional `charts`, `heat`) so `ResearchPanel` renders it; the panel shows `J` frame progress while it runs | One panel, one payload, existing job UI |
| C | Weights and currency | A portfolio's weight = quantity x last close in the position's own currency converted at the last FX rate when every non-base currency has an FX leg in the bars; otherwise returns stay in local currency and the headline says `LOCAL-CURRENCY RETURNS, FX RISK NOT INCLUDED`. Shorts are allowed in `RISK`; the optimizers are long-only. Default portfolio = the only one stored, else the one named `MAIN`, else NOT RUNNABLE listing the names | Positions have quantity and average cost only (Phase 8) |
| D | `RISK` | `RISK [PORTFOLIO] [RANGE=3y] [BENCH=SPY] [CONF=95] [HOR=1]`. Sections: `SUMMARY` (value, annualised vol, beta and correlation to BENCH, max drawdown, HHI, top-1/top-5 weight, effective N), `VAR` (historical, parametric normal, **EVT** (generalised Pareto tail, Vibe `fit_gpd_tail`) at 95 and 99 for HOR days; expected shortfall; money and percent), `CONTRIB` (weight, stand-alone vol, contribution to portfolio variance, beta, historical-VaR contribution), `STRESS` (replays of the **2008 crisis 2008-09-12..2009-03-09, the 2020 crash 2020-02-19..2020-03-23 and the 2022 bear 2022-01-03..2022-10-12**: each holding's own return over the window, weighted at today's weights; a holding with no history over the window is excluded and the row shows `COVERAGE` = covered weight, and the loss is on the covered weight only), `BACKTEST` (Kupiec POF, Christoffersen independence, Basel traffic light of the one-day historical VaR over the last 250 days, Vibe `var_backtest`). Stress windows need daily bars back to 2008: `/api/history` and the Yahoo adapter accept a new range `20Y` (`range=20y&interval=1d` keeps daily bars from 2006-10; `range=max` is downsampled by Yahoo, so it is not used); the recorded fixtures are `yahoo_chart_{spy,aapl}_20y_1d`, and fixture mode slices any shorter daily range (1y, 2y, 3y, 5y) out of the longest recorded daily chart of that symbol. Charts: cumulative return and drawdown of the portfolio at today's weights (labelled `CURRENT WEIGHTS HELD CONSTANT`). Vibe `risk_xray` and `risk` are ported; stress replays are ours | Roadmap row; Vibe has no stress replay |
| E | `PORT OPT` | `PORT OPT [PORTFOLIO] [METHOD=EQVOL\|RP\|MV\|MAXDIV\|HRP\|TURN] [CAP=0.25] [LOOKBACK=252] [RF=0] [TC=0]`. Methods are Vibe's optimizers (`_calc_weights` on one window; `HRP` = `quantlib.portfolio`). `CAP` bounds every weight: SLSQP methods re-solve with bounds, `EQVOL` and `HRP` clip and redistribute pro rata (labelled `CAP BY CLIPPING, NOT RE-OPTIMISED`). `TURN` penalises turnover against the current weights (`TC` = cost per unit turnover). Sections: `TRADES` (current weight, target weight, change, shares and cash to trade at the last close), `COMPARE` (before and after: vol, expected return from the window mean, Sharpe at `RF`, max weight, effective N, turnover), `RISK` (risk contribution per name). The result is a **preview**: key `A` saves the proposal as a new portfolio `<NAME>.OPT` (cost = price at proposal, a note says so); it never edits the original and never places an order. Labelled `ESTIMATED FROM <n> DAYS OF HISTORY, NOT A FORECAST` | Roadmap row "preview trades before applying" |
| F | `PORT ATTR` | `PORT ATTR [PORTFOLIO] [BENCH=SPY] [RANGE=1y]`. `BRINSON` section: Brinson-Fachler by sector (Vibe `attribution`, Carino-linked over monthly sub-periods): portfolio sector weights from today's holdings and Yahoo sectors, **benchmark sector weights from the benchmark ETF's sector weighting** (Yahoo `topHoldings`) and sector returns from the SPDR sector ETFs (XLK XLF XLV XLY XLP XLE XLI XLB XLU XLRE XLC); labelled `TODAY'S HOLDINGS HELD CONSTANT, NOT YOUR HISTORICAL WEIGHTS` and `BENCHMARK SECTORS FROM <ETF> SECTOR WEIGHTS AND SPDR SECTOR ETFS`. `RETURNS` section: **TWR, MWR (XIRR), Modified Dietz and simple return from a stored valuation table** (rows `date, value, flow`; positions carry no dates, so these cannot come from holdings): `PORT ATTR ADD <date> VALUE= [FLOW=]`, `PORT ATTR DEL <date>`, stored in `kv` key `port_vals:<name>` (no migration), `GET/PUT /api/portfolios/{name}/vals`. Fewer than two rows: the section says `NEEDS 2 VALUATIONS`, it does not guess | Positions have no dates |
| G | `FACT` | `FACT <SYM\|PORTFOLIO> [RANGE=3y]`: daily OLS of excess returns on **Fama-French 5 factors + momentum** (Ken French library `F-F_Research_Data_5_Factors_2x3_daily_CSV.zip` and `F-F_Momentum_Factor_daily_CSV.zip`, keyless; provider `kenfrench`, TTL 24 h): alpha (annualised), betas, t-stats (Newey-West, 5 lags), R2, residual vol, factor contribution to return. Headline says `FACTOR DATA ENDS <date>` (the library lags about two months, so the regression window ends there) and `LONG-ONLY US EQUITY FACTORS; NON-US NAMES LOAD ON THEM LOOSELY` for non-US symbols. Vibe `factormodel` ported where it has an OLS/attribution function; the regression driver is ours | Roadmap row |
| H | `QL` | Calculator over the ported library, **only functions with Vibe-number tests**: `QL GARCH <SYM> [H=5]`, `QL OU <SYM>`, `QL COINT <SYM1> <SYM2>`, `QL HEDGE <Y> <X>`, `QL COPULA <SYM1> <SYM2>`, `QL ROLL <SYM>`, `QL AMIHUD <SYM>`, `QL KYLE <SYM>`, `QL VPIN <SYM> [BUCKETS=50]`, `QL EVENT <SYM> DATE=YYYY-MM-DD [BENCH=SPY] [WIN=-5,5] [EST=120]`, `QL DSR SR= N= T= [SKEW= KURT=]`, `QL ADF <SYM>`, `QL HVAR <SYM>`. Bars are daily: `ROLL`, `KYLE`, `VPIN` on daily bars say `DAILY BARS, NOT TICK DATA` (VPIN uses Vibe's volume-bucket classification on the bars it is given). A missing input is NOT RUNNABLE | Roadmap row |
| I | `ALPHA` | `ALPHA [UNIVERSE=TOP100\|WL:<name>\|LIST:A,B,C\|SYN] [RANGE=2y] [FAMILY=...] [H=1,5,10,20]`. Alpha Zoo v1 = **24 to 30 price/volume factors** (Alpha101, Qlib158 and academic families, listed in `quantlib/alpha/ZOO.py`, a test pins the ids and the count) ported verbatim from Vibe (`compute(panel)` on wide frames). The v1 list (29, fixed by the cross-check run): alpha101 001 002 003 004 006 009 012 013 016 021 033 034 101; qlib158 roc10 std20 ma20 beta10 resi10 rsqr20 rank20 corr10 rsv10 wvma20; academic strev illiq retskew mkt_rf rmw smb (`carhart_mom`, `high52w`, `bab` need 252+ bars of warm-up and join later). Factors that need extras (market return, size) get them from the scan's own panel or are skipped with a reason. `TOP100` = the 100 largest US names by market cap from the screener payload; `SYN` = SYN0000..SYN0099 and says `SYNTHETIC DATA, NOT A MARKET`. Per factor: IC mean, IC std, **IR**, t-stat, % of days IC > 0, IC at each horizon (decay), coverage; label by Vibe's rule: **alive** = IC mean > 0.02, IC positive ratio >= 0.55 and |t| > 2; **reversed** = IC mean < -0.02 and |t| > 2; **dead** otherwise. Chart: IC decay of the selected factor; `Enter` opens the factor's formula and meta. The scan is a job with progress; the bars come from `service.history` (cached) with the screener universe. **Lookahead sentinel** (ported test idea): a factor fed bars truncated at day t must give the same value at day t as the full series; the test runs every zoo factor | Roadmap row, "start with 20-30 factors" |
| J | `CORR REGIME` | `CORR REGIME [LIST\|WL:<name>] [WIN=60] [EDGE=0.5]`: Vibe `regime.py` (edge density of the rolling correlation graph, hysteresis fused/diffuse states) on the symbols of the `CORR` panel; sections `EPISODES` (state, start, end, bars, mean density), headline = current state; chart: edge density with thresholds | Roadmap row |
| K | **KITE** (read-only) | See "Kite Connect" below | User decision 2026-10-19 |
| L | Labels and TTLs | Every payload headline says source and age; computed things are named computed. Cache by job hash: results live as long as the bars they used (bars TTL as today); Ken French 24 h; Kite instruments 24 h, quotes 2 s, historical 300 s | Non-negotiables |
| M | Budgets (bench) | `RISK` on a 20-name 3-year portfolio <= 400 ms end to end after the job warmed; `ALPHA` on the SYN 100-name 2-year universe, 24 factors <= 8 s; `PORT OPT` HRP/RP 20 names <= 400 ms; `CORR REGIME` 20 names 2 years <= 300 ms; panel render of any Phase 15 table <= the Phase 13 research budget. Recorded in PERFORMANCE.md; numbers may be re-set once measured, never after the fact to hide a miss | Speed is a feature |

## Kite Connect (decision K): READ-ONLY data

Zerodha Kite Connect is the one allowed paid data source (it needs the user's own paid developer app). Everything is **inert without a key**:
`KEY REQUIRED: set KITE_API_KEY in APIKEYS`. **There is no order placement, no order route and no order tool anywhere**; a test fails if any route
path, tool or module name contains `order`, `orders`, `gtt`, `margins` or `portfolio/holdings` under the Kite code.

| Part | Decision |
|---|---|
| Keys | `KeySpec("kite", ("KITE_API_KEY", "KITE_API_SECRET"), 15, ...)` in `keys.py`, pasted in `APIKEYS`; the secret never leaves the backend. The one-day access token is stored in the key store as hidden field `KITE_ACCESS_TOKEN` (not an input in APIKEYS) with the login date; redacted like every key |
| Login (daily, never automated) | `KITE LOGIN` opens `GET /api/kite/login`, which 302-redirects to `https://kite.zerodha.com/connect/login?v=3&api_key=...` (the key never reaches the frontend). The user registers `http://127.0.0.1:8000/api/kite/callback` as the redirect URL in the Kite developer console. `GET /api/kite/callback?request_token=...&status=success` (loopback only) exchanges it: `POST https://api.kite.trade/session/token` with `checksum = sha256(api_key + request_token + api_secret)`, header `X-Kite-Version: 3`; stores the token; answers an HTML page "LOGGED IN, close this tab". Nothing logs in unattended; no TOTP, no credentials are ever stored |
| Status | `GET /api/kite/status` -> `{state, user, logged_in_at, expires_note}` with `state` one of `NO KEY`, `LOGGED OUT`, `OK`, `KITE LOGIN EXPIRED` (a 403 `TokenException` from any call, or after 06:00 IST of the day after the login). The status bar and `SOURCES` show it; every Kite-backed panel says `KITE LOGIN EXPIRED: run KITE LOGIN` instead of failing |
| Instruments | `GET /instruments` (CSV) cached 24 h in memory and in the `kv` table; symbol map: Yahoo-style `RELIANCE.NS` -> `NSE:RELIANCE`, `.BO` -> `BSE:`, index `^NSEI` -> `NSE:NIFTY 50`, `^NSEBANK` -> `NSE:NIFTY BANK`, futures/options by `tradingsymbol`; MCX roots by name |
| Ticks | One WebSocket `wss://ws.kite.trade?api_key=..&access_token=..` while a Kite symbol is subscribed; binary packets decoded per the documented layout (8-byte LTP, 28/32 index, 44 quote, 184 full; prices /100, /10^7 for CDS); ticks enter the streaming hub with source tag `k` shown as `RT KITE` (like `RT IEX`); off in fixture mode; drops back to Yahoo when logged out |
| Bars | `GET /instruments/historical/{token}/{interval}` (`day`, `minute`..`60minute`) with `oi=1`; chunked to the API's per-call window; 3 requests/s limit respected by `ratelimit`; becomes the first `history` provider **for `.NS`/`.BO`/NFO/MCX symbols only** when logged in |
| Chains | `OMON <NIFTY\|BANKNIFTY\|SYM>.NFO [expiry]` builds the chain from the instruments dump (`NFO-OPT`, `MCX-OPT`) and `GET /quote` (<= 500 instruments per call: bid, ask, last, volume, **OI**); IV and Greeks are computed here with `openterm/quant` only when `R=` (and `Q=`) are typed and are labelled `COMPUTED HERE (BLACK-SCHOLES), NOT VENDOR`; without them the columns say `NEEDS R=` and the OI and quote columns still show. Futures list with OI via `CT` |
| Fixtures | `kite_*` are **doc-shaped (from the Kite Connect v3 documentation) and labelled `NOT a recording`** until the user has a key; the section headline repeats it in fixture mode. `scripts/record_phase15.py` has a `--kite` mode that records real answers once a key and a login exist |

## Functions

| Code | Args | Shows |
|---|---|---|
| `RISK` | `[portfolio] [RANGE] [BENCH] [CONF] [HOR]` | VaR/ES (hist, normal, EVT), beta, drawdown, contributions, stress replays, VaR backtest |
| `PORT OPT` | `[portfolio] [METHOD] [CAP] ...` | Optimizer preview, trades, before/after; `A` saves `<NAME>.OPT` |
| `PORT ATTR` | `[portfolio] [BENCH] [RANGE]`, `ADD`, `DEL` | Brinson-Fachler, TWR / MWR / Dietz / XIRR |
| `FACT` | `<sym\|portfolio> [RANGE]` | FF5 + momentum exposures |
| `QL` | `<calc> ...` | GARCH, OU, cointegration, copula, microstructure, event study, deflated Sharpe |
| `ALPHA` | `[UNIVERSE] [RANGE] [FAMILY] [H]` | Zoo scan: IC / IR / decay, alive / reversed / dead |
| `CORR REGIME` | `[list] [WIN] [EDGE]` | Correlation regime timeline |
| `KITE` | `LOGIN \| STATUS \| LOGOUT` | Login flow and status of the Kite source |

## Build steps (each ends with the gates and a commit; push after each)

1. Spec, fixtures (`scripts/record_phase15.py`), Vibe cross-check script + expected numbers, API and unit tests (strict-xfail per group).
2. `quantlib/` ports (risk, var_backtest, portfolio/HRP, optimizers, attribution, factormodel, timeseries, copula, microstructure, eventstudy, multipletesting, regime), scipy dependency, THIRD_PARTY rows; Vibe numbers pass.
3. Job plumbing (`/api/quant/{fn}`, data file, kinds) + `RISK` + `PORT OPT` + `PORT ATTR` (+ vals routes) + panels.
4. `FACT` (Ken French provider) + `QL`.
5. `ALPHA` zoo + scan job + lookahead sentinel; `CORR REGIME`.
6. Kite backend: keys, login/callback/status, instruments, quotes, historical, chains, WebSocket decoder and `RT KITE`, no-orders test.
7. Kite frontend and integration: `KITE` command, status bar, `APIKEYS` rows, `OMON` Indian chains, `.NS` bars.
8. Docs (COMMANDS, DATA_LIMITS, CHANGELOG, PERFORMANCE), bench, real-backend smoke run, handoff, roadmap.

## Done when
Ported functions pass Vibe's own numbers (cross-check) and their rewritten tests; the lookahead sentinel passes for every zoo factor; alpha scans run as jobs
with a bench budget; every function has an e2e test with data and, where it needs a key, the `KEY REQUIRED` path; Kite works only read-only and its
no-orders test passes; all gates green; bench 24/24 plus the new budgets.

## ALPHA zoo extension (workstream 10)
